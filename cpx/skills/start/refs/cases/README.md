# 케이스 카드

환자 설정을 모델이 즉석에서 지어내지 않게 하려고 미리 써둔 카드다.
`topics.md` 는 채점 기준(감별진단·Red flag·PE 초점)만 담고, 실제 환자는 여기서 나온다.

## 세 층으로 나뉜다

| 층 | 파일 | 성격 | 바뀌는가 |
|---|---|---|---|
| 진단 시나리오 | `NN-<slug>.json` 의 `scenarios[]` | 의학적으로 고정. 검증 대상 | 아니오 |
| 인물 | `personas.json` | 이름·나이·직업·성격·건강정보 수준·ICE | 매번 |
| 표현 변주 | 시나리오의 `variations` | 발병 시점·강도·좌우·유발 상황 | 매번 |

의학적 정확성은 진단 층에만 걸린다. 인물 층은 아무리 흔들어도 임상적으로 틀릴 수 없어서
검증 없이 마음껏 다양화할 수 있다. 가슴통증 하나만 해도 시나리오 6개 × 인물 조합 수천 가지 ×
표현 변주 수십 가지라 같은 환자를 두 번 만나기 어렵다.

## 시나리오 필드

채점표(`checklist.md`)의 항목과 1:1로 대응한다. 채점 항목이 있는데 카드에 답이 없으면 그 항목은 채점 불가다.

| 필드 | 대응 채점 항목 |
|---|---|
| `hpi.onset` ~ `hpi.timing` | I-2 주호소 & 현병력 (20점) |
| `assoc.positive` / `assoc.negative` | I-2 동반 증상 (4점) |
| `redFlags` | I-4 Red Flag 문진 (10점) |
| `pmh` `meds` `allergy` `fh` `sh` | I-5 과거력·약물력·가족력·사회력 (12점) |
| `pe.vitals` `pe.findings` | II. 신체진찰 (20점) |
| 인물의 `personality` `healthLiteracy` | III. PPI (20점) |
| 인물의 `iceStyle` | I-3 ICE (6점) |

- `dx` 는 내부 설정이다. 대화 중 절대 언급하지 않는다.
- `redFlags` 의 키는 학생이 물을 법한 질문, 값은 그때 나올 답이다. 묻지 않으면 말하지 않는다.
- `disclosure.spontaneous` 는 첫 개방형 질문에 먼저 말해도 되는 것, `onlyIfAsked` 는 반드시
  물어야만 나오는 것이다. 이 구분이 유도 질문 추종과 정보 과다 방출을 막는다.
- `{{슬롯}}` 은 `variations` 에서 하나 뽑아 치환한다. 같은 슬롯은 한 세션 내내 같은 값을 유지한다.

## 진찰 소견 처리

`pe.findings` 에 적힌 항목은 그 값이 그대로 나온다. 같은 카드면 누가 진찰하든 같은 소견이 나와야
채점이 일관된다. 다만 세 가지 규칙이 붙는다.

- `pe.wording` — 값은 내용만 고정이고 문장은 그대로 읽지 않는다. 자연스러운 소견 보고로 바꿔 말하되
  수치와 유무는 바꾸지 않는다.
- `pe.default` — 목록에 없는 진찰을 시도하면 "특이소견 없음"으로 답한다. 소견을 새로 지어내지 않는다.
- `pe.outOfScope` — 심전도·영상·혈액검사 요청에는 소견을 주지 않는다. 계획을 말한 것으로만 채점에 반영한다.

활력징후는 고정값이 아니라 밴드다. `pe.vitals` 의 각 항목이 `[하한, 상한]` 이고, 여기서 뽑아
한 세션 내내 그 값을 유지한다. 뽑는 규칙은 `personas.json` 의 `_vitalsRules` 에 있다
(고혈압 보유 시 수축기압 가산, 70세 이상 가산, 짝수 반올림 등).

`pe.vitals.invariant` 는 흔들려도 깨지면 안 되는 조건이다. 폐색전증의 빈맥과 저산소혈증,
대동맥박리의 양팔 혈압차 20 이상 같은 것들로, 위반하면 진단 단서가 사라지거나 다른 진단이 되므로
다시 뽑는다. 활력징후는 채점에서 "확인했는가"만 보기 때문에 값이 흔들려도 점수에는 영향이 없다.

## 확률적 소견

진찰로 잡힐 수도 있고 놓칠 수도 있는 소견이 있다. 제3·제4심음, 갑상선 잡음, 임신 중 생리적 잡음,
케톤산증의 과일 냄새 같은 것들이다. 이런 항목은 값 대신 확률 객체를 쓴다.

```json
"심음 청진": { "p": 0.6, "detected": "빠르고 제3심음이 들린다",
               "notDetected": "빠르고 규칙적이며 제3심음은 뚜렷하게 들리지 않는다" }
```

세션 시작 때 한 번 뽑아 끝까지 고정한다. 학생이 다시 청진해도 답이 바뀌지 않는다.

### 무엇을 확률로 두고 무엇을 확정으로 둘지

원칙은 하나다. 그 질환의 대표 소견은 확정으로 간다. 확률로 돌리는 것은 보조 소견뿐이다.

대표 소견을 흔들면 케이스 자체가 성립하지 않는다. 대동맥판협착의 거친 구출성 잡음,
심내막염의 새 심잡음, 대동맥박리의 확장기 잡음, 충수염의 McBurney 압통과 반발통,
담낭염의 Murphy 징후, 수막염의 경부강직이 여기 해당한다. 이런 항목은 카드의
`pe._deterministicCore` 에 이름을 적어 나중에 실수로 확률화하지 않게 한다.

확률로 돌릴 것은 민감도가 낮거나 검사자에 따라 갈리는 보조 소견이다. 제3·제4심음,
갑상선 잡음, 생리적 잡음, 케톤산증의 과일 냄새, 충수염의 Rovsing·장요근 징후처럼
있으면 도움이 되지만 없다고 진단이 뒤집히지 않는 것들이다.

## 증상과 활력징후 연동

증상만 흔들고 활력징후를 그대로 두면 임상적으로 어긋나는 조합이 생긴다. 자궁외임신에서
어깨끝 통증이 나온다면 복강 내 출혈이 더 진행한 것이므로 혈압이 내려가고 맥박이 올라야 한다.

변주 슬롯 값에 `vitalsShift` 를 달면 그 값이 뽑혔을 때 활력징후가 함께 움직인다.

```json
"shoulderText": [
  { "text": "어깨가 결리진 않아요.", "stage": "early" },
  { "text": "가끔 어깨 끝이 결리는 느낌이 나요.", "stage": "progressing",
    "vitalsShift": { "sbp": -12, "dbp": -8, "hr": 14 } }
]
```

`pe.vitals` 의 밴드는 기본 상태를 뜻하고, 이동은 그 밖으로 나갈 수 있다. 무한정 나가면
다른 진단이 되므로 `pe.vitals.shiftBounds` 로 안전선을 둔다. 같은 증상을 두 슬롯으로
나눠 뽑으면 서로 모순될 수 있으니 슬롯은 하나로 묶는다.

## 뺀 소견 보관

임상적으로 틀리진 않지만 학생을 엉뚱한 쪽으로 끌고 갈 여지가 있어 뺀 소견은 지우지 않고
`pe._archivedFindings` 에 이유와 함께 남긴다. 나중에 판단이 바뀌면 그대로 되살린다.

```json
"_archivedFindings": {
  "심음 청진": { "value": "...", "why": "...", "removedOn": "2026-09-02" }
}
```

`pe.default` 에는 함정이 있다. 진단상 이상이 나와야 하는 진찰인데 `findings` 에 빠져 있으면
"특이소견 없음"이 임상적으로 거짓말이 된다. 그래서 카드를 쓸 때 아래를 반드시 채운다.

1. 활력징후와 전신 외관
2. 해당 계통의 시진·촉진·타진·청진
3. 감별 대상 계통의 핵심 소견 (음성이어도 명시)
4. `topics.md` 의 "PE 초점" 에 적힌 항목 전부

## 인물 뽑는 규칙

`personas.json` 의 `_samplingRules` 에 적혀 있다. 요약하면,

1. `constraints.ageRange` 안에서 나이를, `constraints.sex` 대로 성별을 뽑는다.
2. `constraints.requiredRisk` 는 추첨 결과를 덮어쓴다. 심근경색 케이스에 위험인자가 하나도 없으면
   임상적으로 말이 안 되기 때문이다. `requiredRiskMin` 개수만큼 반드시 포함시킨다.
3. `personality` 와 `healthLiteracy` 는 진단과 무관하게 자유롭게 뽑는다. 이 둘이 PPI 난이도를 만든다.
   과묵형 + 건강정보 낮음 조합은 같은 진단이라도 훨씬 어려운 면담이 된다.
4. `occupationBias` 가 있으면 그 목록에서 60% 확률로, 나머지는 전체에서 뽑는다.

## 도구

`cpx/tools/` 에 두 개가 있다. 규칙이 문서에만 있으면 지켜지지 않으므로 코드로 강제한다.

| 명령 | 하는 일 |
|---|---|
| `python sample_case.py [주호소] [시나리오id]` | 카드 + 인물 + 변주를 조합해 한 세션 분량의 환자 설정을 만들어 보여준다 |
| `python sample_case.py --check 4000` | N회 뽑아 `_validation` 위반 건수를 보고한다. 0건이어야 한다 |
| `python lint_cases.py [파일접두사]` | 카드의 필드 누락·형식 오류·미정의 슬롯·중첩 슬롯을 잡는다 |
| `python check_contradictions.py [파일접두사]` | 한 카드 안에서 서로 어긋나는 진술을 잡는다 (음성 소견과 활력징후 밴드가 부딪히는 경우 등) |

린터가 경고하는 것들은 대부분 채점 불능으로 이어진다. `assoc.negative` 가 없으면 감별 문진을
채점할 수 없고, `disclosure.onlyIfAsked` 가 없으면 묻지 않아도 정보가 다 나와 난이도가 사라진다.

## 쓰는 쪽

- 플러그인(Claude Code) — 스킬이 해당 주호소 파일과 `personas.json` 을 읽고 조합한다.
